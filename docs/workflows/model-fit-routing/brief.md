# 실행 전 Model Fit 도입 기록

2026-08-19에 제품 구현을 시작하기 전 모델 후보를 비교하는 판단 기준을 도입했다. 모델 가용성, 작업 요구와 전환 시 잃게 될 문맥이 달라지므로 고정 모델표 대신 실제 후보와 근거를 기록하도록 했다. [Model Fit 판단 기준](../../../agents/skills/owned/product-development-workflow/references/model-fit.md)

## 결정 기록

- 먼저 보안·데이터 정책, 사용 권한, 필수 기능과 예산을 만족하는 후보를 고른다. 남은 후보는 대표 작업의 평가 근거, 현재 문맥을 유지할 이점, 요구 품질을 충족하는 데 드는 비용과 지연을 고려해 비교한다.
- 실제 전환에는 호스트의 지원과 실행 권한이 필요하다. 현재 모델이 수용 조건을 충족하고 이번 실행에서 전환할 수 없으면 다음 실행의 후보를 기록할 수 있다.
- 이후 발동 조건을 사용자 요청으로 좁혔다. 현재 제품 워크플로우에서는 사용자가 모델 선택이나 비교를 요청할 때 이 기준을 읽는다. [결정 근거](../../decisions/0005-retire-audited-path.md)

## 검증 증거

`./tooling/tests/model_fit_test.sh`는 여섯 시나리오에서 핵심 판단 기준과 기대 결과가 일치하는지 검사한다. 복잡한 작업, 예산 제약, 보안 요건, 비슷한 후보, 전환할 수 없는 환경, 지정 모델과 제약의 충돌을 포함한다.

도입 당시 로컬 정책·시나리오 검사는 통과했다. 두 공급자에 같은 시나리오를 보내는 외부 실행은 수행하지 않았다. [시나리오별 기대값과 검증 범위](../../evals/product-development-workflow-model-fit.md)
