## 문제와 원하는 결과

dotagents 관리자는 owned 스킬을 추가할 때 설치기의 전역·프로젝트 목록과 진단기의 목록을 각각 수정한다. 진단 누락을 고친 이력이 있고, 현재는 실제 설치된 모든 링크를 진단하는 회귀 검사도 있다. 남은 문제는 설치·진단에 같은 스킬 이름을 반복해서 관리하는 비용이다.

P1의 핵심 변경은 **owned 스킬의 선택 원본을 하나로 만들고, 현재 설치 대상과 복구 동작을 유지하는 것**이다. P2의 배포·소유권·외부 스킬·평가와 P3의 환경·프로젝트 지원은 별도 PR에서 구현한다. 기능별 PR에서 서로 다른 정책 변경과 적용 조건을 확인할 수 있도록 범위를 구분했다.

성공 신호는 다음과 같다.

- owned 스킬을 추가·제거할 때 설치기·진단기·목록 준비용 테스트에 스킬 이름을 추가·제거하는 수정이 필요 없다.
- 원본 디렉터리, 발견용 alias, registry 메타데이터라는 남는 작성 지점은 명확하며 누락·불일치가 검사에서 드러난다.
- 기존 5개 스킬을 사용하는 상태에서 설치 대상·원본·백업 기록의 의미가 유지된다.
- 빈 목록이나 잘못된 원본을 정상적인 전체 제거로 처리하지 않는다.
- 파일 전달·발견 경로 검사와 실제 호스트 실행, 모델의 작업 품질을 별도로 보고한다.

## 판단 원칙과 절대 제약

1. 확인된 중복부터 제거한다. 작은 목록 통합에 필수 A/B 설치기 개발을 선행시키지 않는다.
2. 배포 결정은 즉시 반영 링크와 명시적 적용 방식의 장단점으로 판단한다. chezmoi는 후자의 도구 후보이며, 채택·배제 자체를 목표로 삼지 않는다.
3. P1에서는 기존 설치 대상·원본 경로·설치 기록 형식·프로젝트 설치 모드를 유지한다. 신규 스킬의 자동 반영과 진단 기준 원본의 명시를 의도한 변화로 기록한다.
4. 충돌 시 무변경, 명시적 강제 설치의 백업, 설치 실패·INT·TERM의 복구, 변경된 대상 보존과 소유한 링크 제거를 유지한다. 제거 명령 자체의 중단 롤백이나 SIGKILL·전원 차단 복구를 보장하지 않는다.
5. 주 체크아웃은 main에 둔다. 현재 worktree에서 작업하고 실제 홈·다른 프로젝트·인증·세션·기존 `settings.json`을 변경하지 않는다. 필요한 저장소 상태는 읽기 전용으로 확인한다.
6. 프로젝트 고유 규칙·검증 명령은 프로젝트가 소유한다. 공통 규칙·스킬의 행동, 호스트 설정 소유권, 공유 namespace 개편은 목록 통합에 섞지 않는다.
7. 검사 정책과 행동 단언을 약화하지 않는다. 이름을 나열한 테스트 준비 코드는 유도로 바꿀 수 있으나, 비어 있지 않은 집합·핵심 스킬 존재·독립적인 기대 결과를 검증해야 한다.
8. P1에 새 런타임 의존성을 추가하지 않는다. P2·P3는 필요한 기존 도구를 선택적으로 사용하고 범용 설치 프레임워크를 만들지 않는다. 기존 Bash 호환 수준을 유지하며 일반 구현 선택은 실행자가 결정한다.

## P0: 기준선과 변경 범위

### T01 선언 지점·소유 경계 확인

1. 이 문서, 저장소 지침, 현재 worktree의 상태·diff·최근 이력을 읽는다. 이미 확인한 사실을 재조사하지 말고 기준 커밋 이후의 차이만 갱신한다.
2. 설치기 두 목록, 진단기 목록, 원본 디렉터리와 alias, registry, 테스트 준비 코드를 연결한다. 이름별 행동 검증과 단순한 목록 중복을 구분한다.
3. 기존 미커밋 변경을 표시한다. 실제 설정값이나 인증·세션을 수집하지 않는다. 설정 소유권 문제의 원인 조사는 T09 조건이 생길 때 진행한다.

### T02 기준선·누락 재현 확인

1. 같은 상태의 `make check` 결과는 재사용한다. 코드·기준 커밋이 달라졌거나 실패·미확인 영역이 있으면 다시 실행하고 원인을 구분한다.
2. 임시 소스·임시 홈·임시 프로젝트에서 현재 전역·프로젝트 설치 기록을 만든다. 루트 경로를 정규화하고 정렬해 구현 후 일회성 비교에 사용한다. 고정 기대 목록 파일을 새로 관리하지 않는다.
3. 임시 소스에 가상 owned 스킬과 alias·registry 메타데이터를 추가해, 현행 설치·진단에 자동 반영되지 않는 것을 수용 테스트로 재현한다. 테스트는 P1 구현 전 실패와 구현 후 성공을 확인한다.
4. 기존 충돌·백업·롤백·제거·소스 이동·프로젝트 경로 보호 검사를 재사용한다. 같은 테스트를 복제하지 않는다.

## P1: owned 스킬 선택 원본 통합

### T04 책임과 열거 계약

| 역할 | 원본 | 이번 결정 |
|---|---|---|
| 원하는 owned 스킬 집합 | `agents/skills/owned/<name>/SKILL.md` 디렉터리 규칙 | 공용 함수 하나로 열거. 별도 수동 설치 목록을 추가하지 않음 |
| 실제 설치·백업 내역 | 전역 `install.tsv`, 프로젝트 `.dotagents-install.tsv` | 형식과 소유권·제거·복구 역할 유지. 진단의 기대 목록을 대체하지 않음 |
| 스킬 메타데이터 | `agents/registry/skills.toml` | 출처·지원 정보로 유지. 설치 입력·외부 다운로드·프로필 선택 엔진으로 전환하지 않음 |
| 호스트 발견용 alias | `agents/skills/<name>` | 저장소가 관리하는 링크로 유지. 설치기가 원본 checkout 안에 생성하지 않음 |

공용 함수는 전달받은 `agents` 경로에서 owned 스킬 이름을 정렬해 반환한다. 현재 owned 디렉터리는 모두 설치 대상이며, 새 유효 스킬도 이 규칙으로 선택된다. registry의 `optional`·`enabled_by_default`·`profiles`를 이번에 새 설치 정책으로 해석하지 않는다.

다음 입력은 설치 변경 전에 실패한다: 원본 경로 누락, 빈 owned 목록, 구분자·경로로 오해될 수 있는 잘못된 이름, 스킬 디렉터리의 `SKILL.md` 누락. 이름은 소문자 영문·숫자·하이픈 범위로 제한한다. 불완전한 디렉터리를 조용히 제외해 기존 링크를 제거하는 동작도 허용하지 않는다.

### T05 구현·검증·문서

1. 설치기의 전역·프로젝트 스킬 행을 공용 열거로 교체한다. 호스트 진입점·설정·훅의 고정 항목, 충돌 판정, 백업·트랜잭션·retired 처리와 제거 스크립트는 유지한다.
2. 진단기는 **실제 설치된 checkout의 `$installed_agents`**를 공용 함수에 전달한다. 명령을 실행한 worktree의 스킬 집합과 혼동하지 않는다. 설치 기록이 없어도 기존에 가능했던 설치 인식·진단을 유지하고, 아직 설치되지 않은 새 선언도 진단한다.
3. 기존 alias·registry 검사를 보강해 모든 owned 디렉터리와의 누락·중복·원본 경로 불일치를 잡는다. 메타데이터 검증을 위해 설치 런타임에 TOML 파서를 추가하지 않는다.
4. 테스트 준비의 반복 목록은 유도할 수 있다. 핵심 스킬 존재, 실제 기대 경로와 부작용, 기존 스킬의 행동 단언은 유지한다. 모든 기대값을 같은 공용 함수에서 가져오는 검사만으로 완료 판정하지 않는다.
5. 아래 수용 시나리오와 기존 `make check`를 실행한다. 테스트용 `DOTAGENTS_HOME`·`XDG_STATE_HOME`과 임시 프로젝트를 사용하며 실제 홈에 설치하지 않는다.
6. [스킬 안내](../../../agents/skills/README.md)에 추가·제거 절차의 원본을 둔다. 다른 README는 이를 참조하고 registry가 설치 입력이 아님을 명시한다. 영향받은 설치·진단 문서도 실제 상태에 맞춘다.
7. `git diff --check`와 새 파일의 형식·링크를 확인하고 이 문서에 결과를 기록한다. 규칙·어댑터 행동과 생성본은 이번 변경 대상이 아니다. 변경이 필요해지면 원인과 범위를 먼저 재판정한다.

수용 시나리오는 다음과 같다.

| 시나리오 | 확인할 결과 |
|---|---|
| 가상 스킬 추가 | 설치기·진단기·준비 목록 수정 없이 전역·프로젝트 설치에 포함. 기대 이름·경로는 테스트 fixture에서 독립적으로 단언 |
| 설치 전 새 스킬 선언, 설치된 링크 누락 | 전역 진단이 누락을 보고하고 파일을 변경하지 않음 |
| 가상 스킬 제거 후 재설치 | 기존 retired 경로로 관리 링크 제거·해당 백업 복원. 사용자가 바꾼 대상은 보존 |
| 빈 목록·잘못된 이름·불완전한 원본 | 설치 대상·기존 manifest·백업을 변경하지 않고 실패 |
| alias·registry 불일치 | 새 스킬도 이름별 검사 추가 없이 구조 검사에서 실패 |

목표는 중복 수정 지점을 줄이는 것이다. 복구 코드를 유지하므로 설치기 전체의 코드량이나 책임이 크게 줄어든다고 약속하지 않는다. 실제 호스트 실행은 별도 확인 여부를 기록하며 구조 검사로 실행 성공을 대신하지 않는다.

## P2: 기능별 PR로 분리하는 보강

### T03 배포 방식 재검토

사용자의 전체 실행 요청에 따라 격리된 배포 비교와 선택적 환경 프로필을 구현한다. 현행 AI 설치의 기본값을 자동 전환하지 않으며, PR에는 다음 필요에 대한 실익과 비용을 함께 기록한다.

- 여러 기기에서 복원·동기화·설정 차이 관리가 실제 목표가 된다.
- main·worktree 분리 후에도 원하지 않는 원본 변경이 라이브 세션에 반복 반영된다.
- 호스트가 쓰는 설정이 추적 파일을 반복 변경해 현재 방식의 유지 비용이 확인된다.
- 셸·앱·OS 설정까지 관리 범위를 넓히기로 한다.

재검토에서는 즉시 반영과 명시적 적용, diff·드리프트 확인, 여러 기기 관리, 적용 단계와 의존성, 이행·복구 비용을 함께 비교한다. 공식 문서로 판별할 수 없는 구체적 질문이 남을 때만 같은 표본의 제한된 실험을 한다. source·destination뿐 아니라 설정·상태·캐시도 임시 경로에 격리한다.

보존 결과와 구현 수단을 구분한다. 기존 파일 손실 방지·사용자 변경 보존·중단 후 복구 가능성을 비교하되, 현행 트랜잭션과 동일한 구현을 후보의 자격 조건으로 삼지 않는다. 다만 현재 보장하는 중단 복구나 백업 정책이 달라지면 비용·영향과 함께 사용자 결정 사항으로 올린다. 표본 통과를 전체 이전 완료로 보고하지 않는다.

### T09 소유 경계와 고정 항목

사용자가 전체 구현을 승인한 항목을 선택형 managed 전역 설치로 구현했다. `.agents`와 skills는 실제 디렉터리로 두고 owned 항목만 연결하며, 호스트 설정은 사용자 소유 일반 파일로 분리한다. 고정 항목 선언은 설치·진단이 공유한다. legacy 기본값과 기존 프로젝트 링크 모드는 유지하며, legacy에서 managed로의 전환은 명시적 제거·재설치 절차를 따른다. 아래 근거는 개편 전 확인 항목이고 구체적인 동작·이행·보장 범위는 [PR #46](https://github.com/LeeByeongMuk/dotagents/pull/46)이 원본이다.

| 항목 | 시작할 근거 | 먼저 할 작은 확인 |
|---|---|---|
| 호스트 설정 소유권 | 호스트가 만든 추적 파일 변경이 반복됨 | 변경 주체와 키의 역할만 확인. 비밀 값은 수집하지 않음 |
| 공유 `~/.agents` 경로 | 다른 도구의 쓰기가 원본 작업 트리에 영향을 줌 | 실제 경로·소유 주체 확인 |
| 프로젝트 링크 모드 | 사용 부재·프로젝트 규칙과의 충돌이 확인됨 | 요청 범위의 설치 흔적과 사용자 사례. 축소 시 이 모드를 사용하는 복구 테스트도 이행 |
| 고정 설치 항목의 선언 통합 | 새 호스트·고정 항목 추가에서 중복 관리가 반복됨 | 필요한 항목 종류·진단 라벨과 기존 검사 대조 |

### T06 외부 스킬과 T07 평가

T06은 잠긴 출처·선택한 항목·명시한 대상에 한정한 설치·갱신·제거 경로를 구현한다. 기존 도구를 먼저 검토하고 임의 원격 스크립트나 설치 훅을 자동 실행하지 않는다. T07은 이번에 추가된 실제 인터페이스와 문서를 대상으로 같은 `gpt-6.1-sol`·`high`·도구·시작 조건의 제한된 평가를 수행한다. 결과를 일반적인 모델 우열이나 구현 품질로 확대하지 않는다. 대규모 평가나 공급자 간 대결은 추가하지 않는다.

## 남은 범위와 한계

- legacy 기본값은 유지된다. #46의 managed 구조는 선택형이며, 기존 설치에서 명시적 제거·재설치가 필요하다. managed 설정 seed는 사용자 소유로 남아 제거 시 지워지지 않는다. 파일 링크는 원본 변경을 계속 즉시 반영하므로 버전별 snapshot 배포가 아니다.
- 환경 프로필은 선택형 shell/git fragment와 OS별 패키지 안내에서 시작한다. 실제 홈 적용·패키지 설치·Debian 실행은 하지 않았다. chezmoi의 뒤쪽 파일 충돌 전에 앞쪽 파일이 적용되는 동작을 관찰했으며 일괄 rollback·원본 백업 복원을 보장하지 않는다.
- 외부 스킬은 선택 항목의 고정 버전 파일 전달과 출처·소유권을 관리한다. upstream 코드·설치 훅·gstack 환경 준비를 실행하지 않았다. 캐시 GC·다른 state로의 자동 이관·SIGKILL/전원 차단 복구는 범위 밖이다. 선택 CLI와 그 테스트에는 Python 3.11 이상이 필요하다.
- 프로젝트 doctor의 성공은 지침·컨텍스트 위치·검증 안내의 존재를 뜻한다. 실제 프로젝트 검사 통과나 문서 완성도를 보증하지 않는다.
- 실제 호스트의 지침 로딩·훅 신뢰·스킬 실행은 검증하지 않았다. 제한된 모델 평가 결과를 품질 향상·모델 우열로 해석하지 않으며, 실행 인자와 성공 기록을 공급자 측 독립 telemetry로 취급하지 않는다.
- 기존 코드의 별도 결함 후보: 제거기의 백업 복원 조건은 끊어진 심볼릭 링크를 제외하지만 설치기의 retired 복원 조건은 포함한다. 이 차이는 코드 읽기로 확인했고 이번 작업에서는 실행 재현·수정하지 않았다.
- 주 체크아웃은 기존 main을 유지하고 사용자의 기존 `agents/adapters/claude/settings.json` 수정은 그대로 보존했다. 원인·실제 설정값은 수집하지 않았다. 검증용 합성 worktree는 어떤 PR이나 main에도 병합하지 않았다.
