# ADR 0001: 살아있는 컨텍스트 문서 규약

- 날짜: 2026-08-06
- 상태: ACCEPTED

## 맥락

- 모듈의 현재 상태를 설명하는 문서가 없거나 낡아, 에이전트와 사람이 작업마다 코드 전체를 다시 탐색한다.
- 실무에서 모듈별 `.ai-context/` 패턴(도메인 개요, 인터페이스 계약, 연동 지도)이 공통 출발점으로 검증되었다.
- 워크플로우의 런 산출물(lean Brief, audited 단계 문서)은 실행 기록이며, 모듈의 현재 상태를 대신하지 못한다.
- 호스트별 훅 설치·실행은 이 저장소에서 미구현이며, 훅은 특정 호스트 전용이라 Claude Code, Codex, Gemini의 동등성을 깬다.

## 결정

1. dotagents에는 규약과 템플릿만 둔다. 컨텍스트 문서 본문은 각 대상 프로젝트에 산다.
2. 갱신 강제는 공통 규칙과 제품 개발 워크플로우의 완료 게이트에 통합한다. 훅 인프라를 만들지 않는다.
3. 범위는 모듈의 현재 상태를 기술하는 문서 3종(도메인 개요, 인터페이스 계약, 연동 지도)으로 한정한다. 실행 산출물은 기존 lean Brief와 audited 산출물이 담당한다.

## 버린 대안

- 훅 기반 자동 강제: 훅 설치가 미구현이고 호스트 전용이라 3개 호스트 동등성을 깬다. 문서를 생성하는 훅은 결정론적 검증 철학과도 충돌한다.
- 단계별 실행 문서 확장: lean 경로의 "하나의 현행 Brief" 원칙과 충돌하고 audited 산출물과 역할이 겹친다.
- JSON 스키마 선고정: 소비자가 생기기 전에 형식을 고정하지 않는다는 `tooling/schemas` 원칙을 따른다.

## 결과

- `direct` 경로의 작은 수정을 포함해 항상 적용되는 `agents/rules/documentation.md` 규칙이 생긴다.
- lean 경로는 영향받은 컨텍스트 문서 갱신을 COMPLETE 게이트로 요구하고, audited 경로는 7·9단계에서 같은 갱신을 요구한다.
- 기본 구조는 `agents/templates/context-docs/`가 정의하며, 프로젝트별 위치 재정의는 프로젝트 `AGENTS.md`에 기록한다.
- 2026-09-30에 ADR 0005로 audited 경로를 제거해, 컨텍스트 문서 갱신은 lean의 COMPLETE 게이트만 요구한다.
