# ADR 0003: 호스트 진입점 생성

- 날짜: 2026-09-10
- 상태: ACCEPTED

## 맥락

- 설치는 `~/.claude/CLAUDE.md` 같은 호스트 진입점을 얇은 어댑터에 링크했다. 어댑터는 `agents/rules/`의 위치만 가리키고 본문은 담지 않았다.
- 2026-09-10 스크래치 저장소 측정에서 이 포인터가 동작하지 않는다는 것이 확인됐다. 세션은 어댑터 파일 하나만 자동으로 로드했고 규칙 다섯 개를 읽지 않았다. 같은 세션에서 "리팩터링해야 될 듯?"이라는 숙의 표현에 파일을 고쳤고, 커밋에는 `git.md`가 금지하는 트레일러가 붙었다.
- 같은 프롬프트에 `workflow.md` 본문을 넣은 대조 실행은 파일을 고치지 않고 검토 의견만 반환했다. 규칙 문구가 아니라 전달 경로가 문제였다.
- 어댑터에 규칙을 복사하면 호스트 3종에 같은 본문이 중복되어 드리프트가 생기고, `check.sh`의 thin-adapter 검사와도 충돌한다.
- `dotagents.toml`의 `output_root`와 `dist/README.md`는 처음부터 생성본을 전제했고 생성기만 없었다.

## 결정

1. `tooling/scripts/build.sh`가 어댑터와 `agents/rules/*.md`를 합쳐 `dist/<호스트>/`에 최종본을 생성한다. 규칙 원본은 계속 `agents/rules/` 한 곳이고 어댑터는 얇게 유지한다.
2. 설치는 호스트 진입점을 `dist/`의 생성본에 링크한다. `settings.json`처럼 생성 대상이 아닌 파일은 기존 경로를 유지한다.
3. 생성본을 저장소에 커밋하고 `make check`가 원본과의 일치를 검사한다. 원본만 고치고 생성을 잊으면 검사가 실패한다.
4. 규칙 순서는 판단에 먼저 필요한 것부터 둔다. `workflow.md`가 앞이고, 순서 목록에 없는 새 규칙 파일은 이름순으로 뒤에 붙어 누락되지 않는다.

## 버린 대안

- 어댑터에 규칙 인라인: 호스트 3종에 본문이 중복되어 원본이 셋이 된다. thin-adapter 검사를 없애야 한다.
- SessionStart 훅 주입: Claude Code 전용이라 Codex와 Gemini가 규칙을 받지 못한다. ADR 0001이 같은 이유로 훅 기반 강제를 버렸다.
- 포인터 문구 보강: 2026-09-10 측정이 대상으로 삼은 문구가 이미 "직접 읽어야 적용된다"였고 동작하지 않았다.

## 결과

- 호스트가 자동으로 읽는 파일 하나에 규칙 본문이 들어가므로, 모델이 포인터를 따라가지 않아도 규칙이 적용된다.
- 규칙을 고치면 `make build`가 필요하다. 잊으면 `make check`가 잡는다.
- 프로필 조합은 소비자가 없으므로 이번 범위에서 만들지 않는다. `agents/profiles/`는 생성기의 확장 지점으로 남는다.
