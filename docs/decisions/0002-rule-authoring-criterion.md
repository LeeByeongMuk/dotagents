# ADR 0002: 규칙 작성 기준

- 날짜: 2026-09-09
- 상태: ACCEPTED

## 맥락

- 2026-08-04에 실수 방지형 전역 지침을 폐기하고 이 저장소로 교체했다. 그 지침은 절대어 규칙, 사고 순서 절차, 모방용 예시로 과거 모델의 실수를 막으려 했고, 예외 상황에서 모델의 판단을 막았다.
- `docs/designs/product-development-workflow.md`는 과거 모델 보정용 규칙과 키워드 트리거 규칙을 만들지 않는다고 워크플로우 범위에서 선언했다. 그러나 `agents/rules/`, 어댑터, 템플릿에는 사고 순서 절차, 금지어 목록, 모방용 예시 블록이 남아 있었고, 새 규칙 후보를 거를 문장화된 기준이 저장소 전체에는 없었다.

## 결정

1. 규칙에는 모델이 스스로 알 수 없는 정보만 둔다. 승인·중단 경계, 산출물 범위, 기억 대신 확인해야 할 정보, 언어·커밋·코딩 관례가 그것이다.
2. 절차, 형식 제한, 금지어 목록, 모방용 예시 블록은 두지 않는다. 기계 검사가 강제하는 형식은 검사기를 원본으로 두고, 규칙은 검사기의 존재와 이유만 가리킨다.
3. 새 규칙 후보는 "모델이 못 하는 일인가, 모델이 알 수 없는 정보인가"를 묻고 후자만 남긴다. 반복되는 현재 증거가 있는 실패만 예외로 두며, 그 경우 근거를 규칙 옆에 적는다.

## 버린 대안

- 기존 규칙에 예외 주석 추가: 문맥 비용은 그대로이고 예외 목록이 다시 절차가 된다.
- 모델별 규칙 분기: Claude Code, Codex, Gemini의 호스트 동등성을 깬다.

## 결과

- `agents/rules/`, `agents/adapters/`, `agents/templates/`를 이 기준으로 정리했다. 사고 순서 절차와 모방용 예시 블록을 제거하고 자율 경계, 산출물 범위, 확인 트리거 문장으로 대체했다.
- 커밋 메시지 금지 표현의 유일한 원본은 `agents/hooks/commit-message/check.sh`다.
- 2026-09-17에 `agents/rules/git.md`에 남아 있던 Conventional Commits 형식 재진술을 제거하고 검사기를 가리키게 했다. type 목록만 규칙에 남긴다. `tooling/scripts/install.sh`가 `commit-msg` 훅을 자동 설치하지 않아 Codex, Gemini에서는 검사기가 없을 수 있고, 그때 type을 모르면 기본값을 지킬 방법이 없기 때문이다.
- `agents/rules/git.md`의 트레일러 금지는 호스트가 세션 지침으로 서명 트레일러를 주입하는 경우를 포함한다. 모델이 스스로 알 수 없는 사용자 선호이므로 기준 1에 해당한다.
- 호스트 시스템 프롬프트와 겹친다는 이유만으로는 규칙을 지우지 않는다. 호스트 프롬프트는 이 저장소가 통제하지 않고 호스트마다 다르다.
