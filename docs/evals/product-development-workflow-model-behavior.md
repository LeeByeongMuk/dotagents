# 제품 워크플로우 모델 행동 eval

- Date: `2026-08-10`
- Baseline: `5c4cc90`
- Candidate: 이 변경의 PR head
- Models: GPT-5.6 Sol, Claude Opus 5, Claude Fable 5
- Result: 후보 하네스가 평가한 모델별 정책 분기를 모두 충족

## 목적

기존 하네스와 축소 하네스가 같은 제품 상황에서 다음 행동을 어떻게 바꾸는지 확인한다.

1. 현재 PRD·이슈·스펙을 Brief로 재사용하는가
2. 열린 제품 결정이 없을 때 실행 전 의식적 중단을 만들지 않는가
3. 짧은 작업에 구현 서브에이전트나 모델 생성 검토를 추가하지 않는가
4. 장기 고위험 작업에서 Opus 5와 Fable 5의 검증 정책을 구분하는가
5. 모든 모델이 결정론적 프로젝트 검사를 유지하는가

이 평가는 실제 구현 품질이 아니라 하네스가 만드는 실행 결정의 변화를 측정한다.

## 방법

각 모델에 변경 전·후 하네스와 동일한 두 상황을 제공하고 구조화된 JSON 결정을 요청했다.

- `routine`: 모든 제품 결정과 수용 조건을 소유하는 편집 가능한 제품 문서가 있고, 열린 결정이 없는 되돌릴 수 있는 UI 작업
- `long_run`: 모든 결정을 소유하는 편집 가능한 PRD가 있고, 세션 토큰 호환 경계와 결정론적 계약 테스트가 있는 약 2시간의 인증 공급자 마이그레이션

실행은 저장소 지침과 도구 영향을 배제하도록 구성했다.

- GPT-5.6 Sol: `codex exec --ephemeral --ignore-user-config --ignore-rules --skip-git-repo-check -m gpt-5.6-sol -s read-only`
- Claude Opus 5: `claude --print --model claude-opus-5 --effort medium --safe-mode --tools "" --no-session-persistence`
- Claude Fable 5: `claude --print --model claude-fable-5 --effort medium --safe-mode --tools "" --no-session-persistence`

첫 병렬 실행은 결과 래퍼가 zsh의 읽기 전용 변수 `status`를 사용해 수집에 실패했다. 같은 입력을 bash 래퍼로 다시 실행했다. GPT 결과의 첫 재실행은 여러 줄 JSON을 마지막 줄만 보존한 파서 문제로 제외하고, 파서를 고친 동일 입력 재실행을 아래 표에 사용했다.

## 결론과 후속 eval

후보 하네스는 두 상황에서 의도한 행동 계약을 충족했고 기존 하네스에서 관찰된 사전 메시지와 잘못된 모델별 검증 분기를 제거했다. 이 결과는 정책 변경을 PR로 검토할 근거로 충분하다.

실제 결함률과 전체 작업 비용은 아직 검증하지 않았다. 다음 모델 업데이트 전후에는 여러 실제 구현 작업을 고정한 eval 세트로 성공률, 수용 조건 누락, 총 토큰, 지연, 비용을 반복 측정한다.

## 2026-08-20 교차 호스트 eval 기반

`tooling/evals/product-development/`에 Codex와 Claude Code가 같은 13개 사례와 `decision.schema.json`을 사용하는 실행기와 채점기를 추가했다. 기본 저장소 검사는 실제 모델을 호출하지 않고 두 공급자의 fixture와 모의 CLI 어댑터를 검증한다. 실제 실행은 도구를 끄고 입력 6종을 시작 시점에 스냅샷하며, 결과에 adapter revision과 각 입력의 SHA-256 출처를 기록한다.

`plan-only` 사례를 GPT-5.6 Sol과 Claude Opus 5 medium에 실제 실행한 결과, 두 모델 모두 `plan`, 구현 미승인, 제품 원본 작업 없음, 서브에이전트 없음으로 판정했다. Codex는 질문 없이 203 출력 토큰을 사용했고 Claude는 범위와 채널에 관한 중요한 질문 두 개를 포함해 919 출력 토큰을 사용했다. 공급자가 보고하는 입력·캐시 토큰 의미가 달라 두 입력 수치를 직접 비용 비교에 사용하지 않는다.

초기 사례의 질문 상한 1개는 스킬의 실제 계약보다 강했다. 스킬은 질문 수가 아니라 범위·행동·위험·절대 제약을 바꾸는지를 기준으로 하며, 기능 범위와 알림 채널은 모두 중요한 결정이므로 상한을 한 번의 작은 질문 묶음인 3개로 수정했다. 이는 모델 출력에 맞춘 품질 완화가 아니라 공통 계약과 채점 조건의 불일치를 고친 것이다.

Claude 첫 실행에서는 공통 JSON Schema의 draft 메타 필드를 Claude CLI가 거부했다. 저장된 공통 스키마는 유지하고 Claude 실행 어댑터가 전달 시 `$schema` 필드만 제거하도록 수정한 뒤 정상 실행했다. 같은 결과 계약을 유지하면서 공급자별 전송 형식만 얇게 보정하는 설계가 실제로 필요함을 확인했다.

후속 공격적 감사에서는 빈 결과와 단일 공급자가 `--require-all`을 통과하던 오류, Claude가 지원하지 않는 effort의 허위 기록, 공백 증거의 성공 판정, 출처가 다른 결과 혼합, 출력 대상 심볼릭 링크 경쟁, 실행 중 입력 변경 가능성을 재현했다. 현재 회귀 검사는 이 실패들을 거부하며 `create / reuse / link`, 차단 질문, 키워드 없는 audited 선택까지 포함한다. 자동 채점은 증거 배열의 형식과 최소 개수를 확인하고 문장의 시나리오 적합성은 수동 검토 항목으로 남긴다.

최종 고정 계약을 GPT-5.6 Sol과 Claude Opus 5의 medium effort로 13개 전 사례에 실행했다.

| 공급자 | 결과 | 입력 토큰 | 캐시 읽기 | 캐시 쓰기 | 출력 토큰 | 지연 합계 | 보고 비용 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Codex / GPT-5.6 Sol | 13/13 | 147,043 | 20,736 | 0 | 2,328 | 99초 | 미제공 |
| Claude Code / Claude Opus 5 | 13/13 | 26 | 46,421 | 61,131 | 8,880 | 146초 | $0.907175 |

두 공급자는 입력과 캐시를 보고하는 의미가 달라 행 사이 원시 토큰 수를 직접 비교하지 않는다. 이 표는 동일 공급자·모델·effort의 향후 회귀 기준과 전체 실행 비용 신호다.

정적 문맥 예산도 `wc -w`로 비교했다. 이전 일반 실행이 항상 읽던 스킬, Brief 참조, 공통 모델 검증 참조는 합계 2,093단어였다. Model Fit 라우팅을 통합한 새 경로는 공통 스킬과 활성 호스트 참조만 읽어 Codex 1,634단어, Claude Code 1,689단어다. 단어 수 대용치 기준으로 각각 약 22%, 19% 줄었으며, 실제 공급자 토큰 수는 토크나이저와 캐시 정책에 따라 달라진다. fallback Brief를 새로 만들 때만 468단어 템플릿이 추가되고, 실행 가능한 후보가 둘 이상이거나 사용자가 모델 선택을 요청할 때만 1,449단어의 Model Fit 참조를 추가로 읽는다.

## 2026-09-09 Claude Fable 5.1 호스트 참조 eval

- Date: `2026-09-09`
- Baseline: `5faad03` (#20 head)
- Candidate: 이 변경의 PR head
- Models: Claude Fable 5.1, Claude Opus 5. GPT-5.6 Sol은 Codex ChatGPT 계정의 사용량 한도로 실행하지 못했다
- Result: Fable 5용 호스트 참조가 Fable 5.1에서 계약을 위반하지 않아 절 제목만 `Claude Fable 5 and 5.1`로 확장. 문장 추가·삭제 없음

### 목적

1. `references/claude.md`를 `claude-code.md`로 바꾼다. macOS의 대소문자 무시 파일시스템에서 이 파일이 `CLAUDE.md`로 잡혀, Claude Code가 같은 디렉터리의 다른 참조를 읽을 때 검증 정책을 지침으로 자동 로드했다. Codex에서는 일어나지 않아 호스트 동등성을 깨는 문제였다. `codex.md`도 대칭으로 `codex-cli.md`로 바꿨다
2. 2026-08-10에 Fable 5로 측정한 호스트 절이 Fable 5.1에서도 같은 실행 결정을 만드는지 확인한다
3. Anthropic 마이그레이션 가이드가 Fable 5.1에 권하는 위임 지침("독립 하위 작업은 서브에이전트에 위임하고 기다리지 않는다")을 추가하면 결정이 달라지는지 잰다
4. 호스트 참조 없이 공통 정책만 줄 때와 비교해 호스트 절이 실제로 결정을 바꾸는지 확인한다

### 방법

`tooling/evals/product-development/behavior.sh`를 추가했다. 2026-08-10 실행과 같은 두 상황(`routine`, `long_run`)을 `behavior/scenarios.json`에 고정하고, 공통 SKILL.md와 지정한 호스트 참조를 준 뒤 권위 원본 처리, 실행 전 중단, 서브에이전트, 모델 생성 검토 종류를 `behavior/decision.schema.json` 구조로 받는다. 도구는 끄고 medium effort, 조합당 1회 실행했다. 호스트 참조 변형은 세 가지다.

- `current`: 이름만 바꾼 기존 참조
- `candidate`: `current`에 위임 문장 한 줄을 더한 것
- `shared-only`: "호스트 지침 없음" 한 줄만 있는 참조

10회 모두 권위 원본을 재사용하고, 실행 전 중단과 질문이 없으며, 구현 분할용 서브에이전트를 쓰지 않았고, 결정론적 검사(단위 테스트·lint, 계약 테스트)를 포함했다. 총 비용은 $1.43이다.

### 판정

- 위임 문장은 두 상황 모두에서 서브에이전트 수를 바꾸지 않았다. 두 상황에 독립 하위 작업이 없어 효과를 잴 수 없었고, 측정된 이득이 없으므로 ADR 0002 3항에 따라 반영하지 않는다
- `long_run`에서 Fable 5.1은 호스트 절이 있으면 모델 생성 검토를 추가하지 않고, 공통 정책만 있으면 토큰 경계 diff에 주 에이전트 표적 검토 1회를 더했다. 근거는 두 경우 모두 "절대 제약은 계약 테스트가 검사하므로 정확한 검증자를 우선한다"였다. 2026-08-10에 Fable 5는 같은 절 아래 fresh-context 검증자 1회를 선택했으므로, 5.1은 같은 문장을 더 보수적으로 적용한다
- 이 결과는 계약 위반이 아니다. 호스트 절은 fresh-context 검증자를 "결과를 바꿀 수 있는 체크포인트에서만" 허용하는 문장이고, Anthropic 가이드도 Fable 5용 프롬프트가 5.1에서 그대로 동작한다고 밝힌다. 따라서 절 제목만 확장하고 내용은 유지한다
- Opus 5 절은 두 변형에서 같은 결정을 냈고, Anthropic 가이드의 "Opus 5는 스스로 검증하므로 검증 지시를 삭제하라"와 일치한다

### 열린 질문
