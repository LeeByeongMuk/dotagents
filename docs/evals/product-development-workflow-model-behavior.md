# 제품 워크플로우 모델 행동 eval

제품 문서와 작업 조건을 받은 모델이 어떤 경로를 택하고 어떤 검증을 제안하는지 측정했다. 2026-09-30에 GPT-5.6 Sol과 Claude Opus 5.5는 각각 라우팅 12개 사례를 모두 통과했다. 이 평가는 모델이 선언한 결정을 채점한다. 실제 구현의 결함률과 작업 시간은 별도 측정이 필요하다.

## 평가 방법

- **라우팅**은 요청을 `direct`, `plan`, `lean` 중 어디로 보낼지, 구현 권한이 있는지, 기존 제품 문서를 어떻게 사용할지 확인한다. `score.sh --require-all`은 두 공급자가 같은 입력 버전의 모든 사례를 제출해야 통과한다. 채점 항목은 [사례 목록](../../tooling/evals/product-development/cases.json)에서 확인한다.
- **행동**은 되돌릴 수 있는 UI 변경(`routine`)과 세션 호환성이 걸린 인증 공급자 이관(`long_run`)을 비교한다. 두 상황 모두 사용할 제품 문서가 있다. 모델에 제공하는 호스트별 지침을 바꾸고, 기존 문서 재사용·실행 전 중단·서브에이전트·추가 검토 여부를 읽는다. [행동 시나리오](../../tooling/evals/product-development/behavior/scenarios.json)

다음 명령은 저장소 루트에서 실제 모델 호출 없이 고정된 결과를 채점한다. 선택한 모델로 같은 조건을 다시 실행할 때는 모델·effort·입력 파일을 고정하고, 결과는 저장소 밖에 기록한다. [실제 실행과 비교 방법](../../tooling/evals/product-development/README.md)

```sh
tooling/evals/product-development/score.sh --require-all \
  tooling/evals/product-development/fixtures/codex.jsonl \
  tooling/evals/product-development/fixtures/claude.jsonl
```

## 2026-08-10 기존 제품 문서 재사용과 검토 범위

`5c4cc90`의 지침과 축소한 지침을 같은 두 상황에서 비교했다. 세 모델 모두 두 지침에서 기존 제품 문서를 재사용했다. 축소한 지침에서도 세 모델 모두 수용 조건과 결정론적 검사를 제시했다. 결과 기록은 `4091523`에 있다.

| 모델 | 기존 지침에서 관찰한 행동 | 축소한 지침에서 관찰한 행동 |
| --- | --- | --- |
| GPT-5.6 Sol | 두 상황 모두 실행 전에 초안을 제시했다. | 두 상황 모두 바로 실행하고, 이관에서는 계약 테스트를 우선했다. |
| Claude Opus 5 | UI 변경에도 추가 검토를 제안하고, 이관에는 독립 검증자를 제안했다. | UI 변경의 추가 검토를 생략하고, 이관의 위험 지점은 주 에이전트가 검토했다. |
| Claude Fable 5 | 이관의 호환성 경계를 주 에이전트가 검토했다. | 이 경계에서 독립 검증자 1회를 제안했다. |

## 2026-08-20 교차 호스트 eval 기반

GPT-5.6 Sol과 Claude Opus 5를 medium effort로 실행해 당시 라우팅 사례를 각각 13/13 통과했다. `plan-only`에서 두 모델 모두 기획으로 분류하고 구현 권한이 없다고 판단했다. 질문 수의 상한은 범위와 알림 채널처럼 실제 결정을 바꾸는 질문을 한 번에 묶을 수 있게 조정했다. 이때의 사례·스키마와 결과 기록은 `ef50c07`에 있다.

## 2026-09-09 Claude Fable 5.1 호스트 참조 eval

기준 지침은 [PR #20의 실험 커밋](https://github.com/LeeByeongMuk/dotagents/commit/5faad037b3ab91fb5f7cabeeb6ad8408d0ce05eb)을 사용했다. Claude Fable 5.1로 기존 Fable 지침, 위임 지시 한 줄을 더한 지침, 공통 지침만 주는 조건을 비교했다. Claude Opus 5로는 앞의 두 조건을 실행했다. 각 조합을 medium effort로 한 번씩 실행했으며 결과 기록은 `cf56134`에 있다.

Fable 5.1은 기존 지침과 위임 지시를 추가한 지침에서 두 상황 모두 추가 검토를 제안하지 않았다. 공통 지침만 주면 이관에서 주 에이전트 검토 1회를 제안했다. Opus 5에서도 위임 문장에 따른 결정 차이는 없었다. 두 상황에는 독립적으로 맡길 하위 작업이 없어 위임 지시의 이점을 확인할 수 없었다. 기존 Fable 지침을 5.1에도 적용했고, 별도 라우팅 검사에서 Fable 5.1이 당시 13개 사례를 모두 통과했다.

## 2026-09-29 Claude Opus 5.5 호스트 참조 eval

`685216d`를 기준으로 네 가지 조건을 비교했다. 기존 지침, 별도 모델 조항이 없으면 공통 정책을 따른다고 명시한 지침, Opus 5 조항을 5.5까지 확장한 지침, 공통 지침만 주는 조건이다. 각 조합을 medium effort로 한 번씩 실행했다.

기존 지침에서 이관의 위험 지점에 주 에이전트 검토 1회를 제안했다. 나머지 세 조건에서는 두 상황 모두 추가 검토를 제안하지 않았고 결정론적 검사를 유지했다. 공통 지침만으로 같은 계약을 충족해 5.5 전용 조항을 추가할 근거가 없었다. 라우팅은 당시 13/13을 통과했다. 결과 기록은 `b8ed57d`에 있다.

## 2026-09-30 audited 제거 후 라우팅·행동 eval

`10803da`를 기준으로 `audited` 경로를 제거하고 Model Fit 선택을 사용자가 요청한 경우로 좁혔다. 해당 경로를 이름으로 지정하던 사례를 제외해 라우팅 검사가 12개가 됐다. 변경 근거와 평가 기록은 각각 [ADR 0005](../decisions/0005-retire-audited-path.md)와 `a59ba0b`에서 확인할 수 있다.

- GPT-5.6 Sol과 Claude Opus 5.5는 medium effort에서 각각 12/12로 전체 채점을 통과했다. 둘 다 공식 검증 증거가 필요한 사례를 `lean`으로 분류하고 수용 조건과 독립 검토를 제시했다. 제품 결정이 막힌 사례에서는 필요한 질문 하나를 했다.
- Claude Opus 5.5의 행동 평가에서도 두 상황 모두 기존 제품 문서를 재사용하고 추가 서브에이전트나 모델 검토를 제안하지 않았다.

측정 당시의 모델과 사례에 대한 결과다. 자동 채점은 구조화된 결정과 필수 필드를 확인하며, 제안한 검사가 실제 작업에 충분한지는 응답과 구현을 따로 검토해야 한다.
