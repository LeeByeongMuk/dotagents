# 제품 워크플로우 모델 행동 eval

- Date: `2026-08-10`
- Baseline: `5c4cc90`
- Candidate: 이 변경의 PR head
- Models: GPT-5.6 Sol, Claude Opus 5, Claude Fable 5
- Result: 후보 하네스가 평가한 모델별 정책 분기를 모두 충족

## 목적

기존 하네스와 축소 하네스가 같은 제품 상황에서 다음 행동을 어떻게 바꾸는지 확인한다.

1. 현재 PRD·이슈·스펙을 Brief로 재사용하는가
2. 열린 제품 결정이 없을 때 실행 전 의식적 중단을 만들지 않는가
3. 짧은 작업에 구현 서브에이전트나 모델 생성 검토를 추가하지 않는가
4. 장기 고위험 작업에서 Opus 5와 Fable 5의 검증 정책을 구분하는가
5. 모든 모델이 결정론적 프로젝트 검사를 유지하는가

이 평가는 실제 구현 품질이 아니라 하네스가 만드는 실행 결정의 변화를 측정한다.

## 방법

각 모델에 변경 전·후 하네스와 동일한 두 상황을 제공하고 구조화된 JSON 결정을 요청했다.

- `routine`: 모든 제품 결정과 수용 조건을 소유하는 편집 가능한 제품 문서가 있고, 열린 결정이 없는 되돌릴 수 있는 UI 작업
- `long_run`: 모든 결정을 소유하는 편집 가능한 PRD가 있고, 세션 토큰 호환 경계와 결정론적 계약 테스트가 있는 약 2시간의 인증 공급자 마이그레이션

실행은 저장소 지침과 도구 영향을 배제하도록 구성했다.

- GPT-5.6 Sol: `codex exec --ephemeral --ignore-user-config --ignore-rules --skip-git-repo-check -m gpt-5.6-sol -s read-only`
- Claude Opus 5: `claude --print --model claude-opus-5 --effort medium --safe-mode --tools "" --no-session-persistence`
- Claude Fable 5: `claude --print --model claude-fable-5 --effort medium --safe-mode --tools "" --no-session-persistence`

첫 병렬 실행은 결과 래퍼가 zsh의 읽기 전용 변수 `status`를 사용해 수집에 실패했다. 같은 입력을 bash 래퍼로 다시 실행했다. GPT 결과의 첫 재실행은 여러 줄 JSON을 마지막 줄만 보존한 파서 문제로 제외하고, 파서를 고친 동일 입력 재실행을 아래 표에 사용했다.

## 결론과 후속 eval

후보 하네스는 두 상황에서 의도한 행동 계약을 충족했고 기존 하네스에서 관찰된 사전 메시지와 잘못된 모델별 검증 분기를 제거했다. 이 결과는 정책 변경을 PR로 검토할 근거로 충분하다.

실제 결함률과 전체 작업 비용은 아직 검증하지 않았다. 다음 모델 업데이트 전후에는 여러 실제 구현 작업을 고정한 eval 세트로 성공률, 수용 조건 누락, 총 토큰, 지연, 비용을 반복 측정한다.
