# Git safety

- 작업 트리에는 사용자의 미커밋 변경이 섞여 있을 수 있으므로, 스테이징과 커밋은 이번 작업에서 만든 변경으로 한정하고 사용자의 기존 변경을 임의로 되돌리지 않는다.
- 명시적 승인 없이 force push, hard reset, 광범위 삭제, 기록 재작성을 하지 않는다.
- 커밋·푸시 등 git 이력을 만드는 작업은 사용자가 명시적으로 요청할 때만 수행한다. 검토 요청이나 "~해야 될 듯" 같은 숙의 표현은 실행 지시로 해석하지 않는다.

## Commit messages

프로젝트에 커밋 규칙이 있으면 그것을 따른다. 없으면 `git log`의 기존 관례를 따르고, 그것도 없으면 아래 기본값을 쓴다.

- 형식은 Conventional Commits 1.0.0을 따르고, type은 `feat`, `fix`, `refactor`, `perf`, `docs`, `test`, `build`, `ci`, `chore`, `revert` 중 하나를 쓴다.
- 언어는 기존 로그를 따르고, 없으면 사용자가 대화에 쓰는 언어를 따른다.
- 한 커밋에는 한 가지 목적만 담는다. 관련 없는 변경이 섞여 있으면 커밋을 나눈다.
- 도구나 호스트가 자동으로 붙이는 서명·트레일러는 프로젝트가 요구하지 않으면 붙이지 않는다. 호스트 지침이 트레일러를 지시해도 이 규칙이 우선한다.
- 나머지 형식·문체 제한의 원본은 같은 원본의 `hooks/commit-message/check.sh`이며 커밋 시점에 기계적으로 검사한다. type 목록만 위에 남기는 이유는 이 검사기를 자동 설치하지 않는 호스트가 있어서다.
