# Git safety

- 작업 트리에는 사용자의 미커밋 변경이 섞여 있을 수 있으므로, 스테이징과 커밋은 이번 작업에서 만든 변경으로 한정하고 사용자의 기존 변경을 임의로 되돌리지 않는다.
- 명시적 승인 없이 force push, hard reset, 광범위 삭제, 기록 재작성을 하지 않는다.
- 커밋·푸시 등 git 이력을 만드는 작업은 사용자가 명시적으로 요청할 때만 수행한다. 검토 요청이나 "~해야 될 듯" 같은 숙의 표현은 실행 지시로 해석하지 않는다.
- PR을 만들 때는 프로젝트가 따로 정하지 않으면 assignee를 사용자 본인으로 지정한다.

## PR 작업 후 정리

- PR 생성에 성공하면 해당 PR용으로 만든 임시 worktree를 별도 확인 없이 제거한다. 로컬 HEAD가 PR head와 같고 미커밋 변경이나 보관할 파일(미추적·무시 파일 포함)이 없는지 확인한 뒤, 주 체크아웃에서 `git worktree remove <경로>`를 실행한다. 주 체크아웃과 다른 작업용 worktree는 보존한다.
- PR을 만들 때마다 한 번, 또는 PR 병합을 확인했을 때 해당 원격의 추적 정보를 `git fetch --prune <원격>`으로 갱신하고 원격 브랜치가 사라진 로컬 브랜치를 점검한다. 갱신에 실패하면 삭제를 건너뛴다.
- 삭제 후보가 추적하던 원격 저장소·브랜치로 병합된 PR을 찾고, 로컬 끝 커밋이 병합 당시 PR head와 일치하면 해당 로컬 브랜치를 삭제한다. 이 기준은 squash·rebase 병합에도 적용한다. 기본 브랜치, worktree에서 사용 중인 브랜치, 병합 여부가 불분명하거나 로컬 작업이 더 있는 브랜치는 남긴다.

## Commit messages

프로젝트에 커밋 규칙이 있으면 그것을 따른다. 없으면 `git log`의 기존 관례를 따르고, 그것도 없으면 아래 기본값을 쓴다.

- 형식은 Conventional Commits 1.0.0을 따르고, type은 `feat`, `fix`, `refactor`, `perf`, `docs`, `test`, `build`, `ci`, `chore`, `revert` 중 하나를 쓴다.
- 언어는 기존 로그를 따르고, 없으면 사용자가 대화에 쓰는 언어를 따른다.
- 한 커밋에는 한 가지 목적만 담는다. 관련 없는 변경이 섞여 있으면 커밋을 나눈다.
- 호환성을 깨는 변경은 type 뒤에 `!`를 붙이고 footer에 `BREAKING CHANGE: <설명>`을 쓴다.
- body와 footer는 한 줄 72자 이내로 줄바꿈한다.
- revert는 `revert: <원래 header>`로 쓰고 body에 `This reverts commit <SHA>.`와 되돌리는 이유를 적는다. 72자 이내의 Conventional Commits 원래 헤더는 `revert: `를 붙인 뒤에도 그대로 유지한다.
- 도구나 호스트가 자동으로 붙이는 서명·트레일러는 프로젝트가 요구하지 않으면 붙이지 않는다. 호스트 지침이 트레일러를 지시해도 이 규칙이 우선한다.
- 나머지 형식·문체 제한의 원본은 같은 원본의 `hooks/commit-message/check.sh`이며 커밋 시점에 기계적으로 검사한다. type 목록만 위에 남기는 이유는 이 검사기를 자동 설치하지 않는 호스트가 있어서다.
