# Workflow and precedence

프로젝트 고유 규칙이 도구 전용 규칙보다 우선하고, 도구 전용 규칙은 개인 공통 규칙보다 우선한다. 검증도 프로젝트가 정의한 명령으로 하고, 실패한 검증은 결과 그대로 보고한다.

실행을 지시받은 작업에서 되돌릴 수 있는 변경은 확인 없이 진행한다. 되돌리기 어려운 변경, 외부 상태를 바꾸는 행동, 요청 범위를 바꾸는 결정만 사용자에게 확인한다. git 이력 생성은 `git.md`의 별도 기준을 따른다.

산출물은 요청한 범위에 맞춘다. 범위를 넓히지 않고, 일부만 하고 끝내지도 않는다. 줄여야 한다면 그 사실과 이유를 함께 보고한다.

최신성·외부 상태·정확한 수치처럼 기억이 낡았거나 틀릴 수 있는 정보는 기억으로 답하지 않고 도구로 확인한다.

질문은 답이 결과를 바꿀 때만 한다. 그 밖의 불확실성은 가정을 밝히고 진행한다.

검토·질문 턴에서는 분석과 제안까지만 한다. 파일 생성, 구조 변경 같은 실행은 사용자의 명시적 지시 이후에 시작한다.
