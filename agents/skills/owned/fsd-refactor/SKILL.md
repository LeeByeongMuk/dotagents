# FSD Refactor

프로젝트가 실제로 채택한 FSD 규칙을 기준으로 구조를 정리한다. 검토만 요청받으면 조사·분류·제안까지만 하고 파일이나 Git 상태를 바꾸지 않는다. 실행을 명확히 요청받으면 허용된 범위에서 조사부터 검증까지 진행하며 단계마다 고정 승인을 요구하지 않는다. 결과를 바꿀 미해결 범위나 동작 결정만 질문한다.

## 기준과 범위 확인

- 대상의 `AGENTS.md`, 아키텍처·코드 규칙과 현재 컨텍스트 문서를 읽는다. 실제 레이어·슬라이스·세그먼트, 경로 별칭, Public API, 허용된 예외를 코드와 설정에서 확인한다. FSD 채택 근거가 없으면 임의로 도입하지 말고 적용 가능 여부를 보고한다.
- `git status`와 diff로 기존 변경을 확인하고 보존한다. 사용자의 체크아웃을 전환하거나 pull·stash·reset하지 않는다. 격리가 필요하면 프로젝트 정책에 맞는 별도 worktree를 사용한다.
- 패키지 매니저, 스크립트, 경계 검사 설정과 CI에서 실제 검증 명령을 찾는다. 기본 브랜치, 명령, 커버리지 수치나 특정 라이브러리를 가정하지 않는다.

## 위반 인벤토리와 배치 판단

요청한 범위에서 `rg`, import·export 추적과 프로젝트 검사기로 후보를 찾고 실제 코드로 확인한다. 각 항목에 적용 규칙, 파일·소비처 근거, 교정 방식과 검증 방법을 남긴다. 확정 위반, 오탐·허용 예외, 이번 범위 밖 항목을 구분한다. 검색 패턴만으로 위반이나 미사용을 단정하지 않는다.

- 배치는 폴더 이름의 일괄 대응이 아니라 책임, 의존 방향과 실제 소비처로 결정한다. 프로젝트가 허용한 구조와 예외를 우선한다.
- 같은 슬라이스의 책임 분리는 그 슬라이스 안에서 해결한다. 여러 소비처가 있다는 이유만으로 `shared`나 다른 레이어로 승격하지 말고 도메인 책임과 의존 규칙도 확인한다.
- Public API를 통한 접근과 레이어 경계를 함께 점검한다. 내부 구현을 불필요하게 export해 deep import 오류만 숨기지 않는다.
- 삭제 전에는 호출·import뿐 아니라 동적 참조, 라우트·프레임워크 진입점, 설정·외부 소비 계약을 확인한다. 미사용 근거가 부족하면 삭제 후보로 남긴다.

확정된 대상과 교정 계획을 간결하게 알리고 실행한다. 검토 요청이면 이 결과를 전달하고 멈춘다.

## 구조 리팩터링

이동·분리·이름 변경과 필요한 import·Public API 수정을 작은 단위로 수행한다. 파일은 작업 트리에서 옮겨 기존 스테이징 상태를 보존한다. 이동할 파일에 미커밋 변경이 있거나 아직 추적되지 않으면 수정 전에 작업 트리 원본을 비교용으로 확보한다.

- 함수 런타임 동작, 응답·오류 처리, 비동기 순서와 부수 효과를 보존한다. 함수 본문 개선은 별도 범위다.
- JSX·className·레이아웃·표시 문자열은 그대로 옮긴다. 라우트·URL·API 경로와 계약, 쿼리 키 값도 보존한다.
- `enum` → `as const`, `.then()` → `async/await` 같은 전환은 의미가 달라질 수 있으므로 구조 교정에 섞지 않는다. 기능·동작 변경이 필요하면 별도 제안으로 남긴다.
- 삭제·이동 뒤 모든 소비처와 관련 테스트·설정을 갱신한다. 도메인 계약이나 연동 위치가 바뀌면 프로젝트 관례에 따라 해당 컨텍스트 문서도 갱신한다.

## 검증과 완료

- 프로젝트가 정한 타입 검사, lint·경계 검사, 관련 테스트와 필요한 빌드를 실행한다. 변경 위험에 맞춰 기존 동작과 핵심 화면을 확인한다. 실패가 기존 상태인지 이번 변경 때문인지 구분하고, 실행할 수 없는 검사는 이유와 함께 보고한다.
- 인벤토리의 검색·import 추적을 다시 수행해 이번 범위의 확정 위반과 새 경계 위반이 해결됐는지 확인한다. 오탐·예외·미처리 항목을 남기며 저장소 전체 검색 결과 0건을 완료 조건으로 삼지 않는다.
- 이번 작업에서 바꾼 경로만 검토한다. 추적된 경로는 `git diff <시작 커밋> -- <경로…>`와 `git diff --check <시작 커밋> -- <경로…>`로 확인한다. 이동한 파일은 새 경로의 내용을 이동 전 원본과 대조한다. 변경 없이 추적되던 원본은 시작 커밋에서 읽을 수 있다.
- 이번 작업에서 만든 미추적 파일은 내용을 직접 읽고 `git diff --no-index --check -- /dev/null "<새 파일>"`로 공백 오류를 확인한다. 이동한 파일은 `/dev/null` 대신 이동 전 원본을 사용한다. 출력 없는 종료 코드 1은 두 파일의 내용 차이를 뜻한다.
- 최종 보고에는 인벤토리 대비 결과, 실제 검증 명령과 결과, 남은 항목·위험을 담는다. 구조 검사 통과만으로 동작 불변을 보증했다고 쓰지 않는다.

커밋·push·PR은 현재 세션에서 명시적으로 허용된 경우에만 수행한다. 허용된 경우에도 프로젝트 Git 정책과 실제 대상 브랜치를 확인하고, PR에 교정 범위·보존한 계약·검증 근거·남은 항목을 기록한다.
