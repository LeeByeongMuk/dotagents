# 저장소 활동 정리

지정한 기간에 무엇이 바뀌었고 현재 어디까지 완료됐는지 근거와 함께 설명한다. 기본 산출물은 대화 안의 간결한 한국어 보고다. 사용자가 정한 언어·형식·대상 독자를 우선한다.

## 범위 잡기

사용자 요청과 현재 문맥에서 저장소, 수집 방식(로컬/GitHub), 기간·시간대, ref, 작성자와 활동 종류 필터를 확인한다. 현재 저장소는 문맥상 대상일 때만 사용한다. 계정 전체나 이웃 디렉터리를 자동 탐색하지 않는다. 결과를 바꾸는 누락 정보만 질문하고, 합리적으로 정한 기본값은 보고에 밝힌다.

조회 기준 시각, 정확한 `[시작, 종료)` 구간과 시간대, 대상 저장소·ref·확인한 HEAD SHA, 필터, 수집 상태를 남긴다. 여러 저장소라면 각각의 범위와 상태를 구별한다. 사용자의 기여를 묻는 경우 사용자 문맥에서 신원을 확인한다. 저장소 소유자나 `git config`만으로 사용자를 단정하지 않는다.

**반복 실행 결과·체크포인트를 영속 저장해 달라는 요청이 있을 때만** [references/recurring.md](references/recurring.md)를 읽는다. 보통의 일회성 보고에는 실행 기록 파일이 필요 없다.

## 근거 수집

연결된 GitHub 도구를 우선하고, 필요한 조회가 없으면 인증된 `gh`를 사용한다. 인증·도구 부재를 활동 없음으로 해석하지 않는다. 사용자가 지정한 로컬 대체 경로가 있다면 범위·최신성 차이를 밝히고 사용할 수 있다.

### 로컬

`git status --short`, 현재 브랜치, 지정 ref의 전체 HEAD SHA를 확인하고 기간 내 로그에서 관련 diff와 코드를 읽는다. 예를 들어 `git log --format='%H %cI %s' <ref>`, `git show <SHA> -- <관련 경로>`를 활용한다. 기간 조회의 경계는 committer timestamp로 `[시작, 종료)`에 다시 맞추고, 다른 시각 기준을 요청받았다면 이를 명시한다.

미커밋 변경은 기본 수집에서 제외하고 존재만 알린다. 포함 요청이 있으면 커밋된 활동과 구별한다. 원격을 동기화하지 않은 자료는 현재 로컬 checkout 기준이라고 쓴다. 수집을 위해 checkout·pull·stash·reset·작업 트리 정리를 하지 않는다.

### GitHub

요청에 맞는 PR 이벤트(생성·병합 등), 직접 커밋, 리뷰 등을 조회한다. 어떤 이벤트 시각으로 기간을 거르는지 정하고 정확한 경계를 다시 확인한다. PR 본문·diff·현재 상태와 관련 코드, 확인 가능한 CI·테스트·배포 기록을 읽는다. 제목이나 커밋 메시지는 탐색 단서이며 결과를 입증하지 않는다.

페이지와 검색 limit을 확인한다. limit에 닿거나 응답이 잘리면 pagination·기간 분할로 지정 범위를 끝까지 수집한다. 일부 저장소·페이지·필터 조회가 실패하면 `부분 수집` 또는 `실패`와 미확인 범위를 알린다. 전체 범위를 확인하기 전에는 전체 건수나 “활동 없음”을 단정하지 않는다. 확인된 일부 건수는 그 범위와 함께 표시할 수 있다.

## 해석과 귀속

- 활동마다 변경 전 문제, 실제 변화, 검증 결과, 현재 상태 중 근거로 확인되는 내용을 묶는다. 브랜치 구현, 열린 PR, 병합 없는 종료, 병합, 배포, 이후 revert를 구별한다. 병합·릴리스만으로 배포를 입증하지 않는다. 나중에 되돌려진 변경을 현재 성과로 표현하지 않는다.
- PR 작성자, 커밋 작성자, 병합 수행자, 리뷰어를 구별한다. 작성·리뷰·병합 중 실제 역할만 귀속하고, 팀 결과를 개인 구현으로 바꾸지 않는다.
- PR과 그 안의 커밋·merge commit은 같은 변경 사건으로 묶어 중복 성과 집계를 피한다. 건수가 필요하면 PR 수, 커밋 수 등 단위를 나누고 집계 기준을 밝힌다.
- 테스트 파일의 존재와 테스트 통과를 구별한다. 실행 기록이 없으면 검증 미확인으로 쓴다. 성능·매출·사용량 등 수치는 출처, 단위, 측정 기간과 비교 기준·분모가 있는 범위에서만 사용한다. diff 크기를 효과나 생산성으로 환산하지 않는다.
- 주장 옆에 PR 링크·`owner/repo#번호`, 전체 commit SHA 또는 해당 SHA에 고정된 파일 경로/링크를 붙인다. 원격이 없는 로컬 근거는 저장소 식별 경로와 전체 SHA를 사용한다. 관찰과 추론은 구별한다.

## 보고와 부작용

먼저 핵심 변화를 요약하고, 관련 변경을 문제·결과별로 묶어 설명한다. 요청에 유용할 때만 활동별 현재 상태·검증·근거를 표로 정리한다. 마지막에는 수집 범위·기준 시각·제약을 짧게 붙인다. 확인된 활동이 없고 수집이 완전했다면 그 사실만 보고해도 된다.

비공개 저장소의 코드·내부 정보는 대상 독자와 공유 범위에 맞춰 최소한만 인용한다. 공개용 보고에 내부 경로나 비공개 근거를 그대로 옮기지 않는다. 근거가 부족하면 주장 범위를 줄인다.

기본 동작은 읽기와 대화 출력이다. 파일 저장, 이력서·블로그 수정, commit·push·PR, 예약 등록은 이 스킬 사용만으로 허용되지 않으며 명시적으로 요청한 작업 범위를 따른다. 실패 시 완료한 범위와 미확인 원인을 간결하게 보고한다.
