# 반복 실행 기록과 재시도

사용자가 결과·실행 기록·체크포인트의 영속 저장을 요청했을 때만 적용한다. 이 문서는 기록의 연속성을 다루며 예약 등록이나 호스트 설정을 구현하지 않는다.

## 기록의 연속성

사용자가 정한 저장 위치와 기존 기록 형식을 먼저 확인한다. 위치가 없으면 다음 실행에서도 접근 가능한 저장 위치를 정한다. 기존 기록이 없거나 읽히지 않는다는 이유로 첫 실행이라고 판단하지 않는다. 사용자의 첫 실행 확인 또는 기록 복구 없이 새 성공 기준점을 만들지 않는다. 독립적으로 조회 가능한 요청 기간의 대화 보고는 계속할 수 있다.

소스 키는 **저장소 식별자·수집 방식·ref·작성자 필터·활동 종류 필터**의 조합이다. 하나라도 달라지면 다른 소스로 취급한다. 기간과 시간대도 명시하고, 이전 성공 종료 시각을 재사용할 때 같은 순간과 경계 해석이 보존되는지 확인한다.

첫 실행은 사용자가 지정한 기간을 사용하고, 기간이 없으면 합의한 초기 구간을 사용한다. 후속 실행은 같은 소스의 마지막 완전 성공 종료부터 이번 조회 기준 시각까지 정확한 `[시작, 종료)`로 수집한다. 실패 실행 뒤에는 실패한 전체 구간을 포함해 재조회하며, 실패 시각을 새 시작점으로 삼지 않는다.

## 로컬 HEAD와 기간의 합집합

시각 구간의 커밋과 이전 성공 HEAD에서 현재 HEAD까지의 `이전HEAD..현재HEAD` 커밋을 SHA로 합친다. 후자의 커밋은 timestamp가 오래됐어도 포함한다. 뒤늦게 동기화된 커밋을 시각 체크포인트로 놓치지 않기 위해서다.

이전 HEAD를 찾을 수 없거나 현재 HEAD의 조상이 아니면 체크포인트를 유지한다. 이력 단절을 알리고 복구 또는 재수집 범위를 정하기 전까지 성공 기준점을 옮기지 않는다. 수집을 위해 작업 트리나 ref를 바꾸지 않는다.

## 사건 식별과 상태 변화

PR은 `owner/repo#번호`, 커밋은 `owner/repo@전체SHA`처럼 안정적인 ID를 사용한다. 원격이 없는 로컬 저장소는 저장소 식별 경로와 전체 SHA를 사용한다. PR과 관련 커밋을 연결해 같은 사건의 중복 집계를 막는다.

이미 보고한 ID도 상태가 바뀌면 다시 보고한다. 예를 들어 열린 PR이 나중에 병합되거나 병합된 변경이 revert된 경우는 새로 설명할 변화다. ID뿐 아니라 관찰한 상태와 이벤트 시각·근거를 기록한다. 바뀌지 않은 사건은 반복 보고를 줄이되 미완료 항목을 기록에서 버리지 않는다.

## 저장 순서와 복구

실행 기록에는 다음 정보가 있으면 된다. 기존 형식에 맞춰 저장하고 불필요한 별도 파일은 만들지 않는다.

- 실행 식별자, 소스 키, 조회 기준 시각, 정확한 기간·시간대, ref와 HEAD SHA
- `성공 / 부분 수집 / 실패`, 페이지·limit 확인 결과와 미확인 범위
- 근거 ID, 관련 사건·현재 상태, 보고 결과 또는 결과 저장 위치
- 마지막 완전 성공 종료·HEAD와 실패 시 재시도할 전체 구간

결과와 실행 기록을 먼저 저장·확인하고 **모든 수집과 저장이 완료된 뒤** 성공 체크포인트를 갱신한다. 여러 저장소를 하나의 실행으로 관리하면 전부 완료돼야 함께 전진한다. 소스별 체크포인트를 따로 관리하기로 명시한 경우에만 완료된 소스를 독립적으로 전진시킨다.

부분 수집, 인증 실패, 저장 실패는 이전 성공 종료와 HEAD를 유지한다. 활동이 없는 경우도 지정한 전체 범위 수집과 저장이 완료됐다면 성공할 수 있다.

중단된 실행을 재시도할 때 기존 실행 식별자·근거 ID와 저장 결과를 먼저 확인한다. 저장된 결과를 복구·재사용해 중복 생성과 이중 집계를 막고, 기록이 불일치하면 확인될 때까지 체크포인트를 보류한다. 사용자 편집과 다른 실행의 기록을 덮어쓰지 않는다. 안전하게 저장할 수 없으면 결과를 대화로 보고하고 기록 복구가 필요하다고 알린다.
